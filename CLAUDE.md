# echoStorage

## Agent skills

### Issue tracker

Issues live as GitHub issues in `HefKer/echoStorage`, managed with the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles, each label string equal to its name. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context — one `CONTEXT.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.

### Workflow

Solo repo, no pull requests. Work on a short-lived branch, merge it into `main` locally (`git merge --no-ff`), and push. Small changes may be committed directly on `main`. Commit in chunks.

Do not run `gh pr create` or `gh pr merge` — issues are closed by a closing keyword (`Closes #12`) in a commit message, which GitHub honours as soon as that commit reaches `main`.

### Follow-ups

After implementing an issue, sort every review finding you left unfixed and every decision you deferred:

- **Defect**: behaviour or a test does the wrong thing, a spec line is unmet, or a rule written in `CONTEXT.md`, an ADR or `docs/` is broken. Each gets its own issue.
- **Judgement call**: a smell, wording or casing with no written rule behind it. All of them share one issue for the review.
- **Mistaken**: you checked the finding against the code and it does not hold. Name it in your final report with the reason.

Each issue is labelled `needs-triage`, opens with `> *This was generated by AI during review of #N.*`, and states what is there now and what needs deciding. An issue opened this way is a follow-up; when the issue you implemented is itself a follow-up, file defects only and name the judgement calls in your final report.

Done when every finding is sorted and every issue you filed has its number in your final report.
